# Milestone 4: integrated proof and consumer handoff

`python3 runtime/session-service/run-integration-proof.py` exercises the complete
internal-development flow through actual separate CLI processes and the local
XPC service. Public typed Swift methods resolve/verify previews, start/stop
fixtures and reconnect to operation/session snapshots. Their target depends on
the API and result models, never the service implementation.

The committed synthetic title `steam-910001`, build `21`, supplies the observed
installation ID and fingerprint. The runtime plan and active generation use that
same title and installation. The compiler's exported game/build digests must
match those observed inputs; the leased generation must match the active
reference. An intentionally changed canonical export must return CONFLICT, then
a clean export must still verify. No real-game launch is permitted.

After a typed stop, the proof waits for all three exact process identities to be
dead. A second fixture is interrupted by killing the service. A fresh typed
client must see a new service instance, the same exact operation result/event
cursor and an INTERRUPTED session with no living descendants. Replaying the
session key must not relaunch it. Uninstall/GC must remove the one expected object
and leave zero leases; every committed storefront file hash must remain equal.

The `--negative-control` oracle intentionally accepts the modified export. It
must fail only `broken-export-detected-before-clean-control`, while the unchanged
service rejects that export. Final commands and results are recorded below.

The suite is registered in `tools/test-all` with a 300-second outer timeout and
15-second cleanup grace. The existing CI triggers, 15-minute job budget and
CodeQL configuration are unchanged. The registry completeness constant is 48.
[CLIENT_HANDOFF.md](../Specs/CLIENT_HANDOFF.md) documents the public API, event
replay rules, fixture entry points and explicit development limits for #162/#163.

Final local verification:

```sh
python3 runtime/session-service/run-integration-proof.py --negative-control
python3 tools/test-all --selftest
python3 tools/test-all --only runtime-service-swift-test \
  --only runtime-service-xpc-boundary --only runtime-service-operation-proof \
  --only runtime-service-session-proof --only runtime-service-launch-host \
  --only runtime-service-integration
tools/lint.sh
```

The deliberately wrong oracle exits 1, reporting 13 pass / 1 fail, only at the
intended broken-export row. The subsequent clean registered run reports all six
suites PASS, zero failures and zero skips: six Swift tests, boundary 9/9,
operations 38/38, sessions 20/20, host/refusal 4/4 and integration 14/14. Local suite durations were
3.2, 2.3, 33.3, 27.4, 2.3 and 4.3 seconds respectively with warm build caches. These are
local observations, not promised hosted cold-build durations. The runner's
48-suite completeness self-test and repository lint pass.

A scope audit finds changes only in `runtime/session-service/` and `tools/test-all`.
No dependency source, shared runtime, storefront fixture, hosted workflow or
`docs/` decision record changed. The final PR alone carries the closing reference
for #161; milestone PRs #164, #165 and #166 do not.

After the hosted memory constraint was observed in milestone 3, the final
registry retained its live host/refusal control and applied the same measured
>=8 GiB prerequisite to the integration suite. Full session/integration cases
are SKIP on an ineligible host, never credited as passing. Hosted boundary,
operations, Swift tests and live host refusal remain active. All six suites run locally without skips. The hosted result must separately
report the two prerequisite skips and the always-active host/refusal control;
those skips do not credit full process coverage.
