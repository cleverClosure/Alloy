# Complete synthetic Windows session proof

Milestone 4 of #181, 6 October 2026. The registered full-tier
`runtime-service-session-e2e` suite passes all nine cases in 458.6 seconds under
the exclusive lab lock, with no skips. The [recorded result](2026-10-06-session-e2e.json)
contains the actual runtime identities, import/entry observations, process
inventory, correlated events, launch timing and save digest.

A separate authenticated XPC client launches an ARM64 launcher, its x64 game and
an unlisted ARM64 child. Each importing provider DLL observes the selected policy
before guest entry: distinct provider paths, role-specific LANG and working
directory, with FEX present only for the x64 game. The exact mapped builtin FEX
path belongs to the selected verified generation. The unknown child's real DLL
load is denied by the default policy; changing the route to native makes both the
DLL-attach marker and successful load appear. An absent DLL cannot pass this control.

Every live tree has three distinct Windows creation identities, Unix PIDs and
kernel birth identities with the expected parent chain. All remain live until
stop. Final rows preserve the exited history, and independent process-table
checks prove the recorded agent, server, root and all guest PIDs are dead.
Normal stops reach all three cooperative guest markers. The service-crash control
changes the service instance and reconciles the tree. All positive cleanup times
are below ten seconds, within the 25-second bound; all launch replies are below
37 milliseconds, within the five-second bound.

The three refusals occur before guest imports or entry: changed snapshot bytes,
removed generation lease, and a changed byte in an independently materialized
provider. The disposable tamper is restored byte-for-byte with its original mode,
and a fresh valid session then passes. The generation is independently verified
after every positive stop. Every retained event preserves its session, launch
specification, generation and original request correlation UUID, with consecutive
sequence numbers. Pending nonterminal snapshots consume no event sequence.

## Durable save and runtime restoration

The game writes and flushes `Alloy session service save proof v1` followed by one
newline to `S:\saves\session-proof.bin`. Its observed SHA-256 is
`dbd50f6c90a4ed5ee71cec12a12f454393f6896e1c4c6a674c0beec58c1fa1d7`.
The harness checks these bytes after stop, crash and refusals, immediately after
each runtime activation, and before another guest can rewrite the save.

its tree digest is `sha256:25993ff4996a50679f7c52a8401e2771c23a8b3e69b8180f315924fac21ed89a`.
Runtime B is `rtg_10fc5d4f9409cf91ddf5fdcdc03cc84594a7f6f604ab08055ec692ffc5a6a6ac`;
its tree digest is `sha256:c28a3a00cac62d8e2a41e5d196a66f338d8eb922fb2ef1d1c419134d89c735e4`.
The provider variant changes from one to two and back to one. Reactivating the
original package through the existing atomic activation API restores exactly the
original generation, manifest, materialized path and tree digest. The save survives
A → B → A byte for byte. This is restoration through activation, not a new rollback API.

## Verification and limits

Both synthetic packages compile and audit with inherited Wine/CPU archive lineage.
The first full run exposed a polling race: guest output can arrive before its
server-trace native identity. Readiness now waits for all initialized identities;
it does not weaken the identity assertions. A subsequent nine-case direct run and
the final registered suite both pass. Additional deliberately wrong inventory
controls reject missing children, reused native identities and exited rows at
readiness. Repository lint, registry self-tests and all 50 local fast suites pass.

The [client contract](../Specs/CLIENT_HANDOFF.md) and
[complete session protocol](../Specs/SESSION_E2E_V1.md) describe the opt-in endpoint,
result models, reproduction and diagnostics. Raw local pending/request/bootstrap
and trace artifacts remain private; credential scanning is not publication
redaction. The committed result excludes full launch exports and endpoint secrets.

These are unsigned synthetic guests and marker provider DLLs. No graphics-rendering,
storefront or production-game compatibility claim is made. The C/G/S/T namespace
is not host filesystem authorization. No root helper, system installation, account,
shared-runtime modification or production signing is required. Hosted skips below
the unchanged 8 GiB host floor do not receive the local guest coverage's credit.
