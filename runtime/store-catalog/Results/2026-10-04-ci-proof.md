# Hosted catalog gate proof — 4 October 2026

Milestone 6 of issue #102 adds `store-catalog-swift-test` and
`store-catalog-cli-fault-matrix` to the existing `tools/test-all` registry. The
existing CI job already runs its fast tier, following issue #100's consolidation.
The registry now contains 38 suites, 25 fast. No workflow, trigger, schedule,
runner or job is added. Both commands use synthetic libraries, private temporary
stores and loopback HTTP; they do not launch guests or modify shared runtimes.

## Deliberately red, then green

[Scratch PR #137](https://github.com/cleverClosure/Alloy/pull/137) remained a draft
throughout and was closed without merging. Its only deliberate test mutation
changed `installations.count == 2` to `installations.count == 3` in
`discoveryAndRefreshAreDurableOperations`. The gate observed exactly two
installations and reported that precise failed expectation. The other 16 Swift
tests passed, and the separate CLI matrix still reported 163 PASS, zero FAIL.
The fast-tier reporting audit accounted for all 25 selected suites.

| [Inverted assertion](https://github.com/cleverClosure/Alloy/actions/runs/37186257386) | FAIL, one expected assertion | 07:35:41–07:39:11 | 210 s | 900 s |
| [Restored assertion](https://github.com/cleverClosure/Alloy/actions/runs/37186488251) | PASS, 17 tests + 163 matrix cases | 07:40:19–07:44:16 | 237 s | 900 s |

The assertion was restored without changing production code between these two
runs. The restored control's catalog sources and registry match the final
milestone branch. The control commits themselves are excluded from that branch.
The final PR also updates these proof documents and the API's completed status.

An earlier control run exposed a Swift compiler portability issue: an `@main`
entry point named `main.swift` in a multi-file executable failed on the hosted
compiler. Renaming it to `CatalogCLI.swift` resolved that build error before the
assertion experiment above. That initial build failure is not counted as the
negative-control proof.

## Local reproduction and limits

```sh
tools/test-all --selftest
tools/test-all --only store-catalog-swift-test store-catalog-cli-fault-matrix
```

The local registry run passed both suites, reporting selected=2 and reported=2.
The package tests cover all journal state pairs, immutable replay, installation,
repair, storage accounting and process-death recovery. The CLI matrix adds 163
named end-to-end and fault cases; its separate deliberately false byte oracle
exits 1, as recorded in the [CLI proof](2026-10-04-cli-proof.md).

The runner durations above are observed wall-clock job times, including lint
and every existing fast suite, not a benchmark guarantee. Process-death tests
exercise atomic publication/recovery, not physical power-loss injection.
